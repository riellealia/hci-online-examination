## Role permissions and protected access

- **Claimed by:** Natalia
- **Status:** Complete
- **Viewed by others:** No
- **Remarks:** Completed and tested the shared permission and protected-access foundation. The shared permission service defines access for all five roles, rejects inactive accounts and role spoofing, and provides protected-action checks for mutations. The SQLite server validates credentials, issues opaque two-hour sessions, revokes logout tokens, rechecks account state, normalizes roles, and rate-limits failed sign-ins. # Coordination rules

- Only the three team members may appear as claimers, but each person may claim multiple tasks.
- Keep one primary claimer per task; helpers may be written in Remarks.
- Read the relevant detailed plan before starting.
- Coordinate before editing shared authentication, storage, permissions, approvals, or audit code.
- Record the other reviewers under **Viewed by others** before marking a task Complete.
- A cross-role task is Complete only when every affected dashboard is verified.
- Explain blockers and agreed scope changes in Remarks.
- Required work has priority over every optional claim.
